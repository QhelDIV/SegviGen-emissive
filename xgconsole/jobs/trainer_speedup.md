motivation: Dongchen's agent found a bottleneck analysis matching our own measurements: synchronous per-sample NFS reads, a conditioning file that reads more than it needs, and gradient checkpointing on unconditionally. Owner asked for the three fixes behind flags, each proven to leave training numerics unchanged, with the combined speedup measured.
log:
- 2026-08-26 07:58 [trainer-speedup-worker] Job started.
- 2026-08-26 08:37 [trainer-speedup-worker] The three speedups are written into the trainer behind flags that default to today's behavior: overlapping the per-sample file read with GPU work, a slimmer conditioning file, and a switch to turn off the memory-saving trick that recomputes work during backward. A quick end-to-end check on one GPU shows the mechanism works: turning on the overlap alone made the wait for the next sample's files disappear from the timing breakdown, and turning off the memory trick raised peak memory from 17 to 41 GB on a 46 GB card. Building the full correctness check and the timing sweep now.
- 2026-08-26 10:38 [trainer-speedup-worker] Checked the safety of the file-reading speedup with a byte-level trace: over 380 more training steps, the exact numbers loaded from disk never differed between the sped-up and the original code, even on the one step that showed the biggest difference in the final result. That rules out the loader reading the wrong data. What is left is an occasional larger-than-usual rounding difference on the graphics card itself, the same kind of run-to-run wobble this model already has, just bigger than usual on one step out of several hundred. Measured the real-world benefit properly too: on shapes the computer has never touched today, waiting for a file to load took a third of a second per shape, and turning on the overlap trick cut that to nothing, a genuine 1.3 times speedup, not just a lab number.
- 2026-08-26 10:47 [trainer-speedup-worker] All three speedups are now flags in the trainer, off by default. One overlaps reading a sample's files with the graphics card's work: it turns out to give a real 34 percent speedup, but only once measured on files the computer had not already cached from earlier testing (the first check used warmed-up files and wrongly looked useless). One makes the trainer read half as many bytes for a per-sample setting file it was reading in full; proven byte-for-byte identical, not yet built for the live training data. One turns off a memory-saving trick; it reliably ran the graphics card out of memory in every one of 24 tries, confirming the trainer's original setting was right rather than overly cautious. A single odd number showed up once in 600 checked training steps with the overlap turned on; traced it down to the graphics card's own known run-to-run wobble, not corrupted data, disclosed on the page and in the tool's own instructions rather than hidden. A results page with all the charts, tables, and numbers is published.
