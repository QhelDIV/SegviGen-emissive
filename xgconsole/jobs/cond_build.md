motivation: The direct-ovoxel dataset had no cond.pth for any shape, so every run on it had trained with zero conditioning while every baseline received the TexVerse thumbnail. That left conditioning as an uncontrolled difference in the comparison. This workstream builds the missing conditioning from the same thumbnail the baselines get, so the difference can be measured instead of assumed.

- 2026-08-12 17:30 [cond-train] Coverage shipped. build_cond_thumbnail.py calls SegviGen's own img_to_cond unchanged, so preprocessing is Path A's exactly and the only changed input is the image. Tensor contract verified against a Path A cond.pth: (1, 1029, 1024) float32, not the (1, 1024, 1024) the brief assumed, because DINOv3 adds one class token and four register tokens to its 1024 patches. Backfill jobs 240320 and 240351 covered the pre-repartition split; the v2 backfill (job 240602) then ran the same script against the repartitioned split, and coverage today is 71,646 of 71,646 train and 387 of 387 val.
- 2026-08-12 17:30 [cond-train] Dataset defect found, and it reaches past our own run: 591 of 72,546 TexVerse thumbnails (0.81%) are not renders of the object at all but TexVerse's generic placeholder icon, and 530 of the 532 in the two attempted splits are byte-identical, literally the same file. Our loader is the only one that noticed, because it crashes on a single-band image; TEXGen and TRELLIS.2 read the same directory and convert the placeholder to RGB without complaint, so every conditioned baseline sharing the thumbnail has been conditioned on that cube icon for those assets. Recorded with the full census in segvigen_emissive/FACTSHEET_cond_thumbnails.md.
- 2026-08-12 17:30 [cond-train] Zero-write state documented. The 591 placeholder shapes ship with a cond.pth whose tensor is all zeros, an explicit no-conditioning-available marker rather than an absent file; the 147 tiny-object shapes ship with real but weak embeddings built from an uncropped frame. Verified on the live dataset: 40 of 40 sampled placeholders are exactly zero, 40 of 40 sampled tiny-object shapes are nonzero. The distinction matters because an absent file makes a real-conditioning run raise immediately while an all-zero file loads silently, leaving those shapes unconditioned inside a run configured as conditioned. Written up as section 8 of FACTSHEET_cond_thumbnails.md, including the three affected shapes that sit in the frozen 300-shape evaluation list.
- 2026-08-12 17:31 [cond-train] The build shipped and is what every v2 conditioned run consumes: conditioning now covers the dataset completely, built from the same TexVerse thumbnail the baselines receive, so conditioning is no longer an uncontrolled difference in the comparison. It also surfaced a dataset defect nobody had seen, that roughly one shape in a hundred carries a placeholder icon instead of a picture of itself, which affects every model that shares those thumbnails and not only ours. Evaluation continues under separate decisions: the formal frozen-list protocol and the true conditioned-versus-unconditioned ablation are both still open and both wait on the owner.
